# 依赖、执行计划与测试策略

Document State：BASELINED。TASK-V3-008是本次harness工作，原TASK-V3-003是已有费用应用的历史来源。不得把本次基线观察时间回填为原开发时间。

任务划分：prepare由实际developer固定项目目标、来源/假设、版本工件、逐需求设计链接、已有任务/代码基线、风险模型和用例；execute由另一个实际tester执行已固定用例；review由第三个实际reviewer核对材料、风险/发现并依次评估G0–G8；finalize只读取这些已经存在的事实。每个工作单引用前置输出，依赖DONE才可领取。运行库持久化开始、心跳、结束；真实宿主派发凭据在assignment字段保留说明，不能凭一个注册名称推导独立执行。

测试模型先有功能树、对象、风险和测试点，再生成case；每个case具体列出Requirement引用、输入配方、预置、步骤、可观察期望与执行方式，不以一个聚合case声称全部覆盖。P0先执行格式/金额/错误语义，P1覆盖资源阈值与输入不变。

执行策略：Python工具探测后，真实运行已有开发单元命令作为独立重放证据；另用公开CLI逐例执行。本轮每例在启动实际进程前test_execution.start，进程结束后登记精确case版本EVD，并finish。失败自动保留缺陷，harness不自动定责/关闭；先检查真实输入字节与公开界面结果，再交由所属角色修复。

覆盖策略：REQ-01覆盖UTF-8/BOM、列序和结构/编码分区；REQ-02/NFR-001覆盖正常分类、零、长Decimal；REQ-03逐分区覆盖空/日期/类别/金额失败；REQ-04覆盖文件和参数；NFR-002单独覆盖有效位/指数/行数上下限；NFR-003在每个CLI进程前后核对输入和源码，还显式设置缓存目录。

中断与恢复：同一run.json指向同一项目。prepare不重复建项目；execute跳过已有当前版本结果，不把旧case版本结果用于新版本。未正常完成的ACTIVE execution/租约会显式报出，需要核对实际宿主后处理，不能默认PASS。原始输出逐次保留，报告输出包含历史执行统计和当前用例状态。

评审后决定顺序：G0→G1→G2→G3→G4→G5→G6→G7→G8。评审者必须先读当前Gate/证据和输入摘要；assessment返回PASS只是候选。需要真实reviewer登记与该assessment精确匹配的gate_decision证据，再调用gate.decide。G9/G10/G11不由本自测自动推进。
