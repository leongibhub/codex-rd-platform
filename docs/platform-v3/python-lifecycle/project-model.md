# 本次项目模型：核对已有 Python 费用工具

Document State：BASELINED（本次可逆工作基线，非人工批准）。记录时间由每个隔离运行的 provenance 工件保存。Task：TASK-V3-008。

## G0 项目定义

项目章程：复用仓库现有费用 CLI，完成可核查的需求、设计观察、Git 来源、逐需测试与独立评审链。业务理由：用户要求“核对这个费用统计工具，给我一个能看到需求到测试的本机记录，不要再问我问题，也不要改已有应用”，并进一步授权补齐真实生命周期记录。

目标：每个在范围内的 REQ/NFR 都有独立可版本化用例、真实命令与可观察断言；所有工件来源和 Gate 决策角色可核对；能够恢复运行并导出正式报告。成功指标是该明确范围的当前用例状态、追踪缺口和真实评审是否具备，不是预置的全绿数字。

范围：标准库本地 CLI、合成 UTF-8 CSV、确定性金额和输入错误、已公布资源边界、输入与源码不变。保持原应用源文件不变。交付脚本、固定文档、隔离数据库及原始证据。没有网络、依赖安装、实际账单导入、外部发布或新产品开发授权。

干系人/职责：用户提供目标与约束；root 为实际协调者；/root/v3_skill_forward 实际实现本次验证 harness；独立 Tester 和 Reviewer 的身份必须由宿主实际派发后登记，本文不预填不存在的人。人工验收身份尚未获得，状态 PENDING。

初始计划：prepare 固定上下文和需求/设计/计划/模型 → 独立 execute 逐例运行 → Reviewer 核对 G3/G4/G8 材料并依次作 G0–G8 决策 → finalize 只核验外部已登记事实。G9 仍需真实人工决定。步骤时间记录是本次实际发生时间，不回填历史开发时间。

初始风险：RISK-PLC-001 旧 DRAFT 与当前代码差异；RISK-PLC-002 错误测试字节导致错误归因；RISK-PLC-003 模型/用例修订后使用旧证据；RISK-PLC-004 运行中源码变动；RISK-PLC-005 将代理评审或文档基线误认为用户批准。控制分别为固定文件/Git摘要、保存字节/输出、精确版本锁定、运行前后摘要比对、独立身份与不自动签批。

## G1 有界研究与可行性

市场研究适用性：本项目不选择新产品或目标市场，仅验证用户已经指定的现有工具；没有市场规模、用户访谈、客户效果数据，不产生此类结论。竞品分析适用性：不采购、不替换现有应用，因此不做无关竞品优劣或推荐。这个适用性判定需独立 Reviewer 接受后才能用于相应 Gate。

技术证据来自仓库可核对资料：`docs/platform-v3/apps/python_expenses/specification.md`、`initial-model.md`、`design.md`、`implementation.md`、`examples/multistack/python_expenses/expense_analyzer.py`、manifest 和独立 QA 记录。既有源使用 csv/date/Decimal/json/argparse；无新增包安装需求。原设计提及 `analyze_rows`，当前公共实现为 `analyze_csv`，本次架构观察以当前源码为准。

可行性：prepare 必须实际探测当前 Python 并读取现有 Git 记录；execute 使用当前解释器启动原 CLI，保存返回值与结果，不依赖历史 PASS。原独立测试中错误 fixture 将换行写成字面反斜杠+n 的教训，落实为输入字节摘要与明确编码。本项目没有产生新的外部研究资料，历史 QA 只作为风险来源，不导入为本轮测试通过。

## G2 产品解释

产品愿景：让本地使用者知道一份费用 CSV 的分类合计是否精确，以及出错时是否有可靠的命令行失败语义。目标用户是本地 CLI 使用者和核对该工具的 QA/维护者；不是多租户财务系统或支付系统。

用户旅程：准备同一计价单位 CSV → 启动 CLI → 成功时读取排序的类别金额字符串与总额 → 失败时读取 stderr/非零码，不消费成功 JSON。QA 旅程为需求 → 测试点 → 用例 → 实际执行 → 版本化 EVD → 独立评审。

功能优先级：P0 输入合同、精确合计、错误失败语义；P1 公开资源上下限与不改输入。产品可测验收由 requirements.md 逐条定义。未确定且不补造：币种混合、CSV 自动修复、空白物理行的特别语义、性能 SLA、单文件字节上限、网络访问监控。
