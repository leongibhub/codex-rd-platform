# CR-V3-004 — 用无工具文件提案替换不成立的模型沙箱边界

状态：BASELINED。依据：用户明确授权“全部做完”、普通工程选择无需再询问；本记录是实施决策，不是用户验收或安全测试 PASS。

## 原因与保留历史

CR-V3-003 原要求真实 Codex CLI worker。实施期间在临时目录用固定非敏感 sentinel 做了实际隔离探测：`--approve-for-me` 和直接命名 sandbox profile 都能够读写工作区外的测试文件。因此，将控制数据库放在工作区外并不能建立所需的安全边界。没有接触真实控制数据库或凭据。该路径不能继续作为受隔离的生产后端。

既有真实 Codex 生成应用的记录保留：生成了 Python 应用，执行 9 项单元测试；最终工件类型 `DOCUMENTATION` 不符合平台契约，整批工件未被接纳，工作单结果为 FAIL。此记录不证明安全后端、独立测试、正式发布或最终验收通过。

## 需求变更

- REQ-V3-016：保留真实队列、租约、并发、取消、输出预算、恢复和可信 argv 后端。将必须提供 Codex CLI 改为提供真实 Responses HTTPS 传输适配器，`tools=[]`、`tool_choice=none`；模型只能返回结构化文件提案。旧 `type=codex` 必须明确拒绝，不能退回宽权限执行。
- 已有项目维护必须支持宿主显式允许的源码路径，完整内容及 SHA 上下文、创建和基于旧 SHA 的 CAS 更新；不允许模型扫描任意文件、触碰控制文件或直接执行命令。删除不隐式开放，必须走另行显式受控变更。
- 宿主应用提案必须验证完整批次、租约、路径、内容摘要与并发修改。失败回滚、崩溃恢复依据持久化 journal 和实际数据库工件引用，不虚构文件系统与 SQLite 的跨资源原子性。
- REQ-V3-020：保留真实模型试验历史与独立生成应用验证。安全 Responses 传输的 fixture 测试与真实 API 执行分开报告；无 API 凭据则真实 API 验证为 NOT_AVAILABLE，不能借旧 CLI 成功片段改成 PASS。
