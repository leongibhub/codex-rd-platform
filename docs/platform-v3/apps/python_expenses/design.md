# Python CSV 费用分析工具设计

状态：DRAFT；需求：`REQ-MATRIX-PY-01` 至 `REQ-MATRIX-PY-04`；任务：`TASK-V3-003`。

## 模块边界

`expense_analyzer.py` 仅使用 Python 标准库：`csv` 解码与行读取、`datetime.date` 校验日期、`decimal.Decimal` 精确金额、`json` 序列化、`argparse` 命令行处理。将纯函数 `analyze_rows` 与文件/CLI 边界分开，使单元测试不用子进程或真实文件。

处理顺序为：打开 UTF-8-SIG 文件 → 校验 CSV 表头及行形状 → 校验并解析每行 → 在显式精度上下文中用 `Decimal` 累加 → 格式化精确字符串 → 在完全成功后写一行 JSON。任一校验异常在 CLI 边界转换为 `error:` 错误；不会在失败路径写 JSON。

## 表示与错误原则

类别使用去首尾空白后的非空字符串作为键。日期先通过正则限制格式，再用 `date.fromisoformat` 验证真实日历日期。金额先 `Decimal` 解析，再用 `is_finite()` 和比较零拒绝非有限和负值。每个金额限制为 1,000 个有效位、指数绝对值不大于 1,000；CSV 至多 100,000 行。完成整份输入校验后，最小输入指数、最大调整指数和行数共同推导一个足够容纳对齐系数及进位的本地 `Decimal` 上下文精度，避免默认 28 位上下文静默舍入。输出使用 `str(Decimal)`，保留精确值；不会量化、四舍五入或添加货币符号。

CSV 的 `DictReader` 会把缺字段表示为 `None`、多字段收集在 restkey；设计将两者视作格式错误，避免静默丢失数据。没有打开文件或解码失败也作为用户可读的输入错误。

## 风险与限制

输入文件字节大小没有本需求的独立上限；但费用行数、有效位和指数按上述限制约束，以防 Decimal 系数或输出的资源放大。CSV 方言固定为标准逗号/引号规则。无币种语义，因此不同币种不能安全混合，使用者必须在输入前保证同一计价单位。
