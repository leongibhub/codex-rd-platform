# 微信本地记账本规格

`TASK-V3-003` · `REQ-MATRIX-WECHAT` · 状态：`BASELINED`（由 CR-V3-001 的明确范围形成，非人工产品验收）

## 事实、推断与边界

- 已给定：原生微信小程序，新增金额与分类、列表、合计、删除、`wx` 本地存储恢复；使用 Node 测试业务模块，`wx` 仅使用明确的测试替身。
- 默认：金额由用户输入十进制元字符串，领域层转换为整数分（cents）；分类为去首尾空白后的非空文本；不支持编辑、云同步、账户、预算或跨设备数据。
- 未知且不阻塞本范围：用户自定义分类集合、账单日期及多币种。MVP 固定显示记账创建时刻，货币为人民币，分类自由输入。

## 用户流程

1. 用户输入金额（如 `12.34`）和分类（如“餐饮”），点击“新增记录”。
2. 页面校验并以分保存记录；成功后刷新列表与总额，失败时显示可见错误并不写入数据。
3. 用户点击某条记录的删除按钮，记录从当前列表移除并持久化。
4. 小程序重启或页面重新加载时，从本地存储读取记录；丢失或无效存储值降级为空列表。

## 可验证需求与验收

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| REQ-MATRIX-WECHAT-001 | 原生工程结构 | `app.json`、页面 JS/WXML/WXSS 和 `Page` 注册存在；工程不包含伪造 AppID。 |
| REQ-MATRIX-WECHAT-002 | 新增账目 | 合法正金额（最多两位小数）及非空分类生成含唯一 ID、整数 `amountCents`、分类和创建时刻的记录；不合法输入不改变数据。 |
| REQ-MATRIX-WECHAT-003 | 精确合计和列表 | 合计仅由整数分求和；UI 格式化为两位小数，显示类别、时间、金额和空态。 |
| REQ-MATRIX-WECHAT-004 | 删除与恢复 | 删除指定 ID 后写回存储；重新创建 Page adapter 后恢复相同记录和合计。 |
| REQ-MATRIX-WECHAT-005 | 可测试存储边界 | 业务模块不直接依赖全局 `wx`；适配器以 `wx.getStorageSync`/`wx.setStorageSync` 提供存储，并可用显式 fake `wx` 在 Node 验证。 |

## 非功能与限制

- `NFR-MATRIX-WECHAT-001`：所有领域金额以安全整数分存储，拒绝超过 `Number.MAX_SAFE_INTEGER` 的输入或累计值。
- `NFR-MATRIX-WECHAT-002`：数据仅在当前小程序本地存储；删除不可恢复，卸载或清理小程序数据会丢失记录。
- 本地 Node 通过不能代替微信开发者工具导入、原生运行、真机或发布验证；该环境中它们为 `NOT_AVAILABLE`。
